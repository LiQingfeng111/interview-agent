# 这个项目到底是什么（从零开始读的一页）

写给"完全不了解这个项目"的人。不谈亮点，只讲它是怎么跑起来的、
那个黑窗口在干什么、为什么它长得不像别人的平台。

---

## 一、那个黑窗口是什么

```
Starting web UI on http://127.0.0.1:8770 ...
[LLM] 已连接本地模型：DSH 免费中继 · lobsterai/deepseek-flash · http://127.0.0.1:18326/v1
[ui] 已启动: http://127.0.0.1:8770
```

它就是一个 **Python 进程**（`webui.py`），干两件事：

1. 把 `webui.py` 里内嵌的一张 HTML 页面发给浏览器（打开 `http://127.0.0.1:8770` 看到的就是它）
2. 接收浏览器发来的 5 个请求，算出结果返回 JSON

用的是 Python 标准库 `http.server`——**没有 Web 框架、没有数据库服务、没有前端构建**。
关掉这个窗口，浏览器就打不开了；这就是"后台"和"前端"的关系。

那行 `[LLM] 已连接本地模型` 是启动时探测模型的结果：探测到就走真实模型，探测不到就降级 mock（界面右上角会显示）。

---

## 二、五个请求就是这个项目的全部对外面

| 你点的地方 | 浏览器发的请求 | 后端函数 | 它做的事 |
|---|---|---|---|
| 开始面试 | `POST /api/start` | `api_start` | 解析简历 → 建计划 → 建会话 → 出第一问 |
| 提交回答 | `POST /api/answer` | `api_answer` | 评分 → 抽事实 → 判要素 → 出下一问 → 存库 |
| 提前结束 | `POST /api/end` | `api_end` | 收尾出报告 |
| 查看报告 | `GET /api/report` | `api_report` | 汇总五维分数 + 诊断 + 雷达图数据 |
| 后台页 | `GET /api/admin` `GET /api/trend` | `api_admin` `api_trend` | 读 SQLite 做统计 |

跑一遍 `python tools/walkthrough.py`，它会把上面每一步的真实请求和返回值打印出来。

## 三、一轮面试，后端具体做了 7 件事

以"答一句话"为例，真实事件流（`python tools/walkthrough.py` 的输出）：

```
 0 resume.parsed    简历拆成 3 个项目（规则+模型兜底）
 1 plan.built       建提问计划（保证每个项目都问到）
 2 llm.call         [interviewer] 出题 → 34 字
 3 turn.asked       问题落账：阶段 OPENING
 4 llm.call         [evaluator] 评分 → 261 字 JSON
 5 eval.returned    判定=partial，模型判定=partial，无冲突
 6 memory.fact      从回答里抽出「规模=300 份」
 7 memory.fact      抽出「召回率=71%」
 8 llm.call         [interviewer] 出下一问
 9 turn.asked       下一问落账：阶段 SELF_INTRO
```

七件事对应七个模块：

| # | 做什么 | 模块 | 为什么要有 |
|---|---|---|---|
| 1 | 解析简历 | `resume.py` | 后面所有问题都要围绕真实项目问 |
| 2 | 决定问什么 | `state_machine.py` + `probe_tree.py` + `interviewer.py` | 不然就是随机抽题、问三轮还在原地 |
| 3 | 打分 | `evaluator`（在 `session.py` 调用） | 每轮给五维分与判定 |
| 4 | 记住候选人说过什么 | `memory.py` | 才能发现"你刚说 300 份，怎么现在说 1000 份" |
| 5 | 留痕 | `ledger.py` | 每一笔都能对上：谁调的、多少钱、判了什么 |
| 6 | 自我体检 | `invariants.py` | 8 条规则，fatal 就不采纳这次输出 |
| 7 | 存下来 | `persist.py` | 关窗口不丢，能接着答 |

## 四、为什么别人的是"平台"，我们的是"这东西"

**因为交付形态不同，不是能力不同。**

| | 别人的平台（如 interview-guide） | 我们 |
|---|---|---|
| 语言/框架 | Java 25 + Spring Boot 4.1 + Spring AI | Python 3.12，标准库，**零第三方依赖** |
| 数据库 | PostgreSQL + pgvector | SQLite 单文件 |
| 中间件 | Redis Stream（异步任务队列） | 进程内直接跑 |
| 前端 | React 18 + TS + Vite，独立工程 | 一个内嵌 HTML 字符串 |
| 启动 | Docker Compose（PG + Redis + MinIO + 后端 + 前端） | **双击一个 .bat** |
| 部署 | 一台服务器对外提供服务 | 本机 127.0.0.1，只有你自己能开 |

同样的能力（出题、追问、评分、报告），他们做成了"一套系统"，我们做成了"一个程序"。

**这个选择是故意的，代价也真实：**

- 好处：任何人拿到这台机器都能直接跑，不需要装 Docker、不需要配数据库、不需要 `npm install`
- 坏处：看起来像玩具；不能多人同时用；不能部署到公网（无鉴权）；界面上限低

如果要把"这东西"变成"平台"，缺的不是功能，是三层工程：
1. 静态资源与模板拆分（HTML 从 Python 字符串里搬出去）
2. 真正的会话与鉴权（登录、权限、并发隔离）
3. 容器化部署（Dockerfile 已写，但本机没有 Docker，**从未 build 过**）

## 六、一句话总结

> 这是一个**跑在本机的 Python 程序**：用一个黑窗口同时当服务器和入口，
> 把"出题—回答—评分—追问—报告"做成一条可审计的流水线，
> 把每一步都写进事件账本，让分数能被追问"凭什么"。
>
> 它不是平台，因为它没做平台该有的那三层工程；它也不是玩具，因为它的判定过程可复现、可校准、可体检。
