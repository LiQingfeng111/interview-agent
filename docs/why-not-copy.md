# 借别人经验时用的判断标准（为什么抄这个、不抄那个）

写这份文档的起因：用户连问三次——"我们怎么把别人的经验用上来？别人有的我们为什么没有？
是真的不重要还是不值得？为什么不值得？"

**结论先说**：绝大多数"我们没有"的东西，不是不重要，也不是不值得——
是**当时根本没被列进选项**（没做竞品扫描就开始写代码）。这是流程错误，不是判断错误。
但把选项列出来之后，确实有 40% 的东西该明确判"不做"，理由写在这里，免得下次又从头吵。

---

## 一、判断一条"别人有我们没有"的机制值不值得抄：四道闸

按顺序过，任一道不过就**不抄**：

### 闸 1：它会不会改变"这个项目想证明的那件事"？

这个项目想证明的是：**Agent 的判定可以做成可审计、可复现、可校准的系统。**
不是"能陪人练面试"（那是产品目标，很多项目已经做到了）。

- 通过：阶段简报、SSOT 守卫、判定权归属、校准置信区间 → 都在加强"判定可信"
- 不通过：面试日历、飞书会议邀请解析、多模型配置页面 → 和"判定可信"无关

### 闸 2：我能不能**验证它真的有效**？

不能验证的功能，写进去就是吹牛。这条最狠，砍掉了一大批：

| 想抄的 | 为什么不能抄 |
|---|---|
| 真实时语音（WebSocket + 流式 ASR/TTS） | 没有第二个人来试，我无法量化"打断延迟从 800ms 降到 300ms 值不值"；本机也没条件调音频链路 |
| 编码题沙箱执行 | 需要容器隔离，本机没 Docker（连 Dockerfile 都没 build 过），做出来等于没验证过 |
| 六种面试官风格 | 能抄，但"严厉拷打"和"温和鼓励"对同一段回答的分数影响有多大？我没有第二个标注者来判定哪个更对，所以风格只能做**措辞变化**，不能做成"评分变化" |
| 跨会话成长看板 | ✅ 能验证（分数都在库里，聚合即可）→ 抄了 |

### 闸 3：它的成本是不是由我承担，收益由别人享受？

- 面试日历 / HR 侧 / 多租户 → 收益在"团队用"，我一个人维护不动，且实习作品集里没人会点开日历
- 题库扩到 2000 → 边际收益递减（722 已经覆盖 46 个话题），但生成成本是我的时间和模型额度

### 闸 4：抄进来之后，能不能证明"没让现状变差"？

这条今天真踩了：我把"总时长→阶段题量分配"抄进来，权重手写成 1/2/6/5/1，
默认 24 轮分出来是 2/3/10/8/2，结果一条评估场景 `probe_shallow_04` 从 PASS 掉到 FAIL（死磕检测被触发）。
修法不是调权重糊过去，而是：**默认轮次必须与旧行为逐字一致**，只在用户改总时长时才偏离。

## 三、"为什么不值得"要能说成一句话

判断标准最后要能压成一句话，否则下次还会重吵。三种句式：

1. **和命题无关**："它让面试更像面试，但没让分数更可信。"（日历、语气风格）
2. **无法验证**："我能把它写出来，但没法证明它比现在好。"（真实时语音、沙箱）
3. **成本错配**："维护成本在我，收益在团队场景，而这个项目的读者是一个人。"（多租户、HR 侧）

反过来，**值得抄的东西有共同特征**：
- 能把已有数据重新组织一遍（不用新增模型调用）→ 简报、趋势
- 能变成一条可执行的断言（测试）→ SSOT 守卫
- 能让"判定"更不可辩驳 → 阈值权威、置信区间

## 四、这次真正的教训

问题不在"该不该抄"，在**顺序**：

```
❌ 我的实际顺序：想需求 → 写实现 → 用户质疑 → 才去搜竞品 → 发现缺一堆
✅ 正确顺序：  搜竞品 → 列机制清单 → 过四道闸 → 写实现 → 用守卫测试证明没变差
```

代价是真实的：题库从 0 写到 722 才发现别人早就整理成 SKILL.md 知识库；
会话持久化在"关窗口全丢"之后才补；多用户是用户问了才想起来。

**下次任何"做一个 X"的任务，第一步就是搜 X 的现有实现，而不是先写代码。**
