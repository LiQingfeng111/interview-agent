# 20 分钟技术叙述稿：模拟面试 Agent（可审计版）

这份文档不是 README，是**给面试场景准备的讲稿**：
先讲它是什么，再按"一轮面试的数据流"展开，然后用五个真实踩坑证明难点在哪，
最后给数据与边界。每节都标了建议时长与"可能被追问 → 怎么答"。

---

## 0. 一句话定位（30 秒）

> 这是一个跑在本机的面试练习程序。它做的事和别人一样：出题、追问、评分、出报告。
> 不一样的是：**它把"分数怎么来的"做成了可审计、可复现、可校准的东西**——
> 每一轮都记进事件账本，评分证据必须能在原话里找到，
> 判定权在阈值而不是模型，阈值本身对着 57 条人工标注做过交叉验证并报了置信区间。

## 2. 一轮面试的数据流（4 分钟，核心）

```
浏览器 ──POST /api/answer──► webui.Handler
                              │  ① 鉴权（签名 cookie → 用户）
                              ▼
                        session.step()
                              │
   ┌──────────────────────────┼───────────────────────────┐
   │ ② evaluator              │ ③ memory                  │ ④ probe_tree
   │ 五维打分 + 判定          │ 抽事实 + 矛盾检测         │ 要素覆盖/回避/未答出
   │ （证据必须原文可查）     │ （旧值 vs 新值）          │ （决定下一个追问什么）
   └──────────────────────────┼───────────────────────────┘
                              ▼
                    ⑤ state_machine.maybe_advance()
                    总时长 → 阶段预算 → 阶段题量 → 木梯层级
                              ▼
                    ⑥ interviewer.next_question()  ──LLM──► 下一问
                              ▼
                    ⑦ ledger.append(...)  每一笔入账
                    ⑧ invariants.check()  8 条规则，fatal 不采纳
                    ⑨ persist.save()      SQLite 快照
                              ▼
浏览器 ◄──{"question", "progress", "card"}── webui
```

**要强调的一句**：LLM 只做语义判断（这段话说没说到点子上），
所有**记账类判断**（要素是否关闭、问了第几次、预算还剩多少、什么时候结束）
都在代码里，是确定性的、可测的。

## 3. 五个真实踩坑（8 分钟，这是全场的重心）

### 坑 1：模型判定覆盖了校准出来的阈值（最贵的一个）

**现象**：我做了 57 条标注、扫出阈值（pass≥2.8），但报告里的判定跟分数对不上。
**查因**：`normalize_eval` 里写着"模型给了合法 verdict 就用模型的"——
12 条标注里 **10 条**是模型说了算，校准形同虚设。
**修**：判定权收归阈值；模型判定降级为对照字段 `model_verdict`，
不一致时记 `verdict_conflict`，并由 INV-05 报警。
**面试可讲的一句**：*这不是 bug 修复，是"可信度声明"的修复——
我原本在 README 里写"阈值经过校准"，实际上它只影响 17% 的情况。*

### 坑 2：把"阶段题量按总时长分配"抄进来，评估场景当场退化

**现象**：借 interview-guide 的做法，权重手写 1/2/6/5/1，默认 24 轮分出来 2/3/10/8/2，
评估回归里 `probe_shallow_04` 从 PASS 掉到 FAIL（死磕检测被触发）。
**修**：加硬约束——**默认轮次必须与旧配置逐字一致**，只有用户改总时长时才偏离。
**可讲的一句**：*外来机制要先证明"不改变现状"，再谈"带来改进"。*

### 坑 3：探针树本来是"影子状态"

**现象**：早期深挖状态靠提示词记忆，问过什么全靠模型自觉，出现"同一要素问第四遍"。
**修**：把探针树（要素覆盖/回避/未答出/每要素最多 2 次）做成**主状态**，
并加了 parity 测试：3 个种子 × 4 种回答序列 × 3 个项目，新旧实现输出必须一致，才允许切主路径。
**可讲的一句**：*改状态机最怕静默改变行为，所以先做影子对照，再切主路径。*

### 坑 4：页面挡住了，接口没挡

**现象**：给 `/admin` 页面加了角色检查，普通用户直接请求 `/api/admin`
拿到了**所有人的会话列表**。
**修**：页面与接口各自拦一次，`/api/admin`、`/api/users` 都加角色判断。
**可讲的一句**：*页面级权限是装饰品，接口级权限才是权限。*

### 坑 5：登录态把"被操作对象"覆盖了

**现象**：后台新建用户永远失败，返回"用户名已存在"，界面还没提示。
**查因**：登录中间件无条件把 payload 里的 `user` 改写成当前登录者，
于是"新建 student1"实际在"再建一个 admin"。
**修**：`with_actor()` 只对会话类接口覆盖 `user`；账号管理接口的 `user` 是操作对象。4 条单测锁住。

> 坑 4、5 都是"做了鉴权之后才出现的新 bug"，可以顺势讲：
> **每加一层抽象，都会带来只属于这层的 bug，所以要成对地加断言。**

## 4. 校准与数据（3 分钟）

| 指标 | 数值 | 说明 |
|---|---|---|
| 人工标注 | 57 条（train 35 / holdout 22） | 单标注者（我），局限见下 |
| 5 折交叉验证一致率 | **80%** | 全量 57 条 |
| bootstrap 95% 置信区间 | **81% [70%, 91%]**，跨度 21pp | 1000 次重采样 |
| mock 模式一致率 | 89%（阈值 3.2/2.0） | mock 是模板，仅验流程 |
| 判定稳定性 | 同答案 ×3 次判定一致 12/12 | 平均分波动 0.0~0.6 |
| 成本实测 | 2 轮基线 ¥0.0017；开教练 ¥0.0043（2.6×） | 每轮 token/成本/延迟入账 |
| 不变量体检 | fatal 0 · warn 0 | 8 条规则 |

**主动说的局限**（面试官最想听这个）：
- 标注只有我一个人 → 80% 是"与我自己标准的一致率"，**不证明标准正确**
- 置信区间跨度 21pp → 57 条样本太少，点估计别当精确值
- 题库生成题只抽查了 5 条，未做全量人工复核
- OTel 导出没有对真实 Langfuse 实例验证过
- Docker 镜像未 build 过（本机无 Docker），只能证明"启动参数与静态配置一致"

## 5. 和别人的差别（2 分钟）

| 维度 | 同类项目常见做法 | 我们 |
|---|---|---|
| 判定依据 | 模型直接给分/给结论 | 模型判语义，**阈值判结论**，冲突留痕 |
| 可复现 | 无 | cassette 重放：同指纹不重复调模型，快照逐字段比对 |
| 自检 | 无 | 8 条运行时不变量，fatal → 输出不采纳 |
| 校准 | 多数没做；一个把"测 judge 与人的一致率"写在 roadmap | 已做 K 折 CV + bootstrap CI |
| 上下文管理 | real-mock 用模型压缩步骤（有二次编造风险） | 结构化聚合（简报），**不新增模型调用** |
| 部署形态 | Java/PG/Redis/React 的完整平台 | 单进程零依赖（**这是取舍，不是优势**） |

> 一句话收束：*别人在做面试产品，我在做一个能被追问"凭什么"的判定系统。*

## 6. 如果只有 3 分钟，讲这三句

1. **体系**：一轮面试背后有 9 个动作，每个都留痕；LLM 只做语义，记账在代码里。
2. **最难的坑**：模型判定覆盖了校准阈值——我原来以为"校准过"，其实只影响 17%。
3. **证据**：57 条标注、5 折 CV 80%、CI [70, 91]、314 条测试、8 关门禁全绿。

## 7. 预判问题与答法（3 分钟自检）

| 可能被问 | 怎么答 |
|---|---|
| 这不就是调 prompt 吗？ | 调 prompt 决定"说得好不好"，我关心"判定靠不靠得住"：阈值谁说了算、证据能不能查、同样的回答会不会今天 pass 明天 fail——这三件都在代码里，不在 prompt 里 |
| 80% 一致率有什么意义？ | 它只说明"和我的标准像"，不说明标准对。所以我报区间、报标注者数量，并把它写成局限而不是卖点 |
| 为什么不用 LangGraph？ | 我需要的是确定性状态机 + 账本；框架能省编排代码，但省不掉"判定权归属"和"可复现"这两个真正的问题 |
| 为什么界面这么简陋？ | 有意的：零依赖双击可跑。要做平台就得加登录、并发、容器编排——登录已经加了，其余列在 `docs/PLATFORM-GAP.md` |
| 数据凭什么信？ | 别信点估计：看区间 [70, 91]、看 314 条测试、看 8 关门禁、看每场的 fatal/warn 计数 |
| 如果重做一次？ | 先搜同类实现再动手。我写题库写到 722 题才发现别人早把知识库做成 SKILL.md——顺序错了，这是真教训 |
