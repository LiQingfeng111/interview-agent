# 网络基础：网卡、IP、端口、监听、局域网（配实物证据）

这份文档只回答一件事：**"程序在哪儿打开了门，谁能走进来"**。
每个结论后面都跟一句你机器上的实测输出。

---

## 1. 网卡是什么

**网卡 = 操作系统用来收发数据包的"接口"。** 一块网卡就是一个出口，每个出口有自己的地址。

你机器上现在有 6 个出口：

```
$ ip -brief addr        （WSL 侧）
lo               UNKNOWN  127.0.0.1/8            ← 回环：假网卡，数据不出机器
eth0             UP       172.22.57.73/20        ← WSL 的网卡
docker0          DOWN     172.17.0.1/16          ← Docker 建的虚拟网桥
br-86ce...       UP       172.19.0.1/16          ← compose 建的网络

（Windows 侧）
WLAN             10.4.163.79/22                  ← 真的无线网卡，连着你家/学校 WiFi
vEthernet (WSL)  172.22.48.1/20                  ← 给 WSL 用的虚拟网卡
Tailscale        100.90.97.27                    ← VPN 虚拟网卡
```

关键点：**`lo`（回环）是一块"假网卡"**，数据包在里面绕一圈就回来了，**从不经过真实网线/无线**。
所以绑在 `127.0.0.1` 上的服务，别人物理上没有任何路径能到达。

---

## 2. IP 和端口不是一个东西

| 概念 | 类比 | 例子 |
|---|---|---|
| **IP** | 一栋楼的门牌号 | `10.4.163.79`、`1.1.1.1`、`127.0.0.1` |
| **端口** | 楼里的房间号 | `8770`、`80`、`443`、`53` |

- `1.1.1.1` 是 **IP**（Cloudflare 的 DNS 服务器地址），不是端口
- 完整写法是 `IP:端口`，比如 `1.1.1.1:53`（DNS 服务）
- 你的服务是 `10.4.163.79:8770` 或 `127.0.0.1:8770`

## 3. "监听"是谁对谁

程序做的事只有一件：

> **向操作系统申请：我要在「某个地址:某个端口」上等连接。**

主语是**程序**，宾语是**自己机器上的地址**。程序不是在"监听别人"，是在**打开自己的一个门**。

实测（起了一个 `python -m http.server 8803 --bind 0.0.0.0`）：

```
Get-NetTCPConnection -LocalPort 8803 -State Listen
→ LocalAddress 0.0.0.0  LocalPort 8803  State Listen  OwningProcess 30148

Get-Process -Id 30148
→ Id 30148  ProcessName python
  Path C:\Users\...\python.exe
```

这条记录是**内核**里的，程序退出它就消失。所以：

- 程序"在哪里打开" = 内核 socket 表里的一条 `(地址, 端口) → 进程`
- 你 `netstat` 看到的是**内核的记录**，不是程序自己写的日志

## 4. `--host` 到底改了什么（有对照实验）

跑 `python tools/net_demo.py`，它会同时起两个一模一样的服务，只有一个参数不同：

```
访问地址                     结果
----------------------------------------------------
127.0.0.1:8801           通  ['127.0.0.1', 8801]     ← 只开回环门
10.4.163.79:8801         不通 (URLError)            ← 换成网卡地址就进不来
127.0.0.1:8802           通  ['0.0.0.0', 8802]      ← 开了所有门
10.4.163.79:8802         通  ['0.0.0.0', 8802]      ← 网卡地址也能进
```

**同一份代码，只改 `--host`，谁能进来完全变了。**

| 写法 | 含义 | 结果 |
|---|---|---|
| `--host 127.0.0.1` | 只在 `lo` 假网卡上开门 | 只有本机能访问 |
| `--host 0.0.0.0` | 在所有真实网卡上都开门 | 局域网内都能访问 |
| `--host 10.4.163.79` | 只在 WLAN 这块网卡开门 | 只有从 WLAN 进来的能访问 |

`0.0.0.0` 不是一台机器的地址，是**"本机所有网卡"的占位写法**。

## 5. 局域网：定义、范围、边界

**定义**：一批设备在同一个子网里，彼此之间不经过网关就能直接通信。

你的数字（实测）：

```
你的地址   10.4.163.79
掩码       255.255.252.0   (即 /22)
子网       10.4.160.0/22
范围       10.4.160.0 ~ 10.4.163.255
可用地址   约 1022 个
网关       10.4.163.254
```

**"局域网内任何人" = 上面这个范围内、能连到你 8770 端口的设备。**

再往外就出界了，因为 `10.x` 是**私网地址**——互联网上不存在这个地址，必须经过 NAT 转换才能出去：

| 私网段 | 谁在用 |
|---|---|
| `10.0.0.0/8` | 你现在的 WiFi |
| `172.16.0.0/12` | WSL 虚拟网卡 172.22.x |
| `192.168.0.0/16` | 家里路由器常见 |

### 三个边界，从近到远

```
① 本机        127.0.0.1                        ← 只有自己
② 局域网      10.4.160.0~10.4.163.255          ← 同子网设备（实测通/不通要看隔离策略）
③ 互联网      需要公网 IP + 端口映射，或 Tailscale 这类虚拟局域网
```

你机器上的 `100.90.97.27`（Tailscale）就是第三种：**虚拟局域网**，
加入同一个 tailnet 的设备互相能访问，不需要公网 IP。

## 6. Docker 会不会单独占一块磁盘

**不会单独占一块磁盘或分区。** 它的数据是**一个目录**：

```
/var/lib/docker                 ← Docker 的全部数据（镜像层、容器可写层、元数据）
实测占用 350 MB
```

而这个目录在 WSL 的虚拟磁盘里，虚拟磁盘是 Windows 上的**一个文件**：

```
E:\WSL\Ubuntu\ext4.vhdx         实测 50.66 GB
```

所以空间链条是：

```
Docker 数据目录(350MB)
   └─ 在 WSL 的 ext4 文件系统里
        └─ 在一块 1007GB 的虚拟磁盘上（df 显示 /dev/sdd）
             └─ 实际是 E 盘上的一个 50.66GB 的 ext4.vhdx 文件
```

顺带一个真实的坑：**`.vhdx` 只增不减**。你删了容器，文件不会自动缩小，
想回收要在管理员 PowerShell 里 `wsl --manage Ubuntu --set-sparse true` 或压缩它。
这也是"为什么装了 Docker 之后 E 盘少了几十 G"的直接原因。

---

## 7. 一句话记住全部

> 程序向内核申请一个「地址:端口」等待连接；
> 地址决定**哪个网卡上的门开着**，端口决定**是哪一扇门**；
> `127.0.0.1` 只在机器内部，`0.0.0.0` 是所有网卡；
> 局域网 = 同一个子网内不经过网关就能到达的范围；出这个范围要公网 IP 或虚拟局域网。
